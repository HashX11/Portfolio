_build - how index.html and the PDF are regenerated
===================================================

index.html is GENERATED. Do not hand-edit it; edit the sources here
and re-run the build, or your change is lost on the next rebuild.

  index.base.html   the original v8.3 markup, near enough untouched
  _gate.html        the desktop/mobile gate (markup + CSS + script)
  _nav.css          anchor navigation, the CSS half
  _nav.js           anchor navigation - one scroller for every table
                    of contents (top bar, right rail, index, sheet)
  _pgscan.css       the Al Tall capture's on-glass HUD
  _pgscan.js        the Al Tall photogrammetry capture (WebGL)
  _i18n.css         Arabic typography and right-to-left
  _i18n.js          the Arabic/English layer (see below)
  i18n-ar.json      the Arabic dictionary - THE file to edit for wording
  i18n-en.json      every English string on the page, regenerated by
                    i18n_extract.py; input to the coverage report only
  i18n_extract.py   pulls the English strings out of the built index.html
  i18n_status.py    what is still English, what is runtime-only
  _mobile.css       the mobile build's stylesheet
  _mobile.js        the mobile build's behaviour
  imgdims.py        reads the pixel size of every bitmap in assets/
                    and writes img-dims.json
  img-dims.json     that map - regenerate it whenever assets change
  build.py          splices all of the above into index.base.html and
                    writes ../index.html

  python imgdims.py     # only when assets/ changes
  python build.py

build.py is idempotent - it always starts from index.base.html, so
running it twice is the same as running it once. If any of its edits
fails to find its target it stops with MISSING PATCH TARGET instead of
writing a broken file.

WHY EVERY <img> GETS A width/height
-----------------------------------
Almost every picture on the page is loading="lazy" and none of them
declared a size, so an unloaded picture was a zero-height box. The page
was therefore 7 035 px shorter at first paint than when it finished
loading, and an anchor jump - the top bar, the rail, the index, the
phone's contents sheet - resolved its destination against that shorter
page. You landed, the imagery decoded, everything below slid down, and
you were reading a heading two or three projects above the one you had
clicked. build.py stamps the real pixel size from img-dims.json, which
gives the browser the aspect ratio before the bytes arrive.

Three CSS rules had to move for that to take: `.natural img` and
`.munigrid > .sheet img` both declared `aspect-ratio: auto`, which
overrides the ratio the attributes supply, and the three `.posterw`
plates are shrink-to-fit (margin:0 auto in a grid), so their <img> at
width:100% had nothing to resolve against until it loaded. build.py
drops the two declarations and gives each plate a definite width.
Verified: the page height is now identical before and after every
image on it has loaded, in both builds.

If you add pictures, re-run imgdims.py. build.py refuses to build if
any <img> has no entry in the map.

ARABIC
------
The English markup is the source of truth. Arabic is a dictionary laid over it
at run time, keyed by the English text itself, so nothing in index.base.html
carries an id and a newly written English paragraph simply shows in English
until it is given a line in i18n-ar.json.

  python i18n_extract.py    # refresh the list of English strings
  python i18n_status.py -m  # what is still English
  ...edit i18n-ar.json...
  python build.py

The unit of translation is a BLOCK - any element with a direct text child, taken
whole with its inline <b>/<em>. That matters: Arabic word order moves, so a
sentence translated in three pieces around its <b> tags comes out as nonsense.
Values may use {{0}}, {{1}} … for the element's non-text children (icons,
images, anything with an id); those nodes are MOVED into the translated content
rather than rebuilt, so the scan's live ALT readout and the viewer's triangle
counter keep writing to the node that is actually on screen.

Strings a script writes later - the contents sheet, the scan captions, the 3D
viewer's status line - are caught by a MutationObserver running the same pass,
so they only need a dictionary entry, not a code change.

Three things the Arabic build must never inherit from the English one, all
handled in _i18n.css and build.py:
  * letter-spacing - it prises the cursive joins apart. Zeroed everywhere.
  * text-transform:uppercase - there is no case in Arabic; it only costs the
    tracking design.
  * per-character span splitting - the headline stagger and the read-along
    profile reveal wrap every letter in its own <span>, which makes each letter
    its own text run and stops it joining. Both fall back to word units.
Four scenes stay left-to-right on purpose because their scripts or their art
direction depend on the axis: the REAL|TWIN split hero, the before/after wiper,
the mobile swipe strips, and the sticky scan viewport.

Switching language reloads the page (?lang=ar) and returns you to the chapter
you were reading. The choice is remembered in localStorage; the gate asks once.
Not translated: the two PDFs and the CV, which are English documents.

pdf/ - the portfolio PDF
------------------------
  print.html    an older 29-page draft; the shipped document is the
                45-page ../_pdf/print.html + ../_pdf/pages.js
  resize.py     downsamples assets/img into ../_pdf/img via headless
                Chrome:  python resize.py 1250 0.66   (share build)
                         python resize.py 1650 0.82   (print build)
  mkpdf.py      renders _pdf/print.html to PDF:
                         python mkpdf.py Hashem-Dankar-Portfolio.pdf
  cdp.py        minimal Chrome DevTools Protocol driver (stdlib only)

Both scripts need print.html served over http (they load
http://localhost:8777/_pdf/print.html), so serve the portfolio folder:

  python -m http.server 8777

The share PDF and the print PDF differ only in the image set in
_pdf/img, so the order is: resize at 1250/0.66, render the share PDF,
resize at 1650/0.82, render the print PDF, then resize back to
1250/0.66 so the folder ships with the share set.

Requires Python 3 and Google Chrome. Nothing else.
